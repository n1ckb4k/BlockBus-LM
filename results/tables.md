# Results tables

Generated by `scripts/analyze_results.py` from the JSON metrics in `runs/` and `results/benchmark.json`. All losses are teacher-forced next-character cross-entropy in nats per character unless labeled otherwise. Test was not used for model selection. Lower is better.

The main model is `joint_frozen_long`: a 1,600-step joint subset-dropout stage followed by a 1,600-step frozen-shared block-specialization stage. The clean-pipeline check is `joint_pretrained_shared`, which starts from an independently trained dense 4-layer shared trunk and trains the three blocks from scratch for 1,600 steps.

## Selective loading efficiency

Checkpoint bytes include the shared file plus only the selected block files; the manifest and Python/PyTorch file overhead are excluded from the logical sum but included in the on-disk directory size in `benchmark.json`. Read transfer is the Windows process I/O counter, which includes some runtime and metadata reads in addition to the checkpoint files. Load latency is CPU-only and the OS cache had already seen the files, so these are not cold SSD reads. Read counters did not fall after the first repeat in the reported run, so logical checkpoint bytes are the cleaner measure of selective loading. See the benchmark JSON for raw counters and generation samples.
